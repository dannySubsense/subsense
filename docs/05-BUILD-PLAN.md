# Build Plan

## 0. Evidence base — complete for this pass

Preserve the corpus; create discovery documents; query Lore; record the no-results finding. Exit when Danny can review evidence-backed choices rather than speculative design.

## 1. Editorial and rights decisions

Danny selects a first tracer project and complementary entry; confirms title/date/status, credits, permissions, and approved media; decides public identity/contact and whether Constellations appears at launch. Record decisions in `docs/06-DECISION-LOG.md` and Lore.

## 2. Content-ready tracer

Create manifests outside the corpus, citing original paths; prepare only approved delivery derivatives; outline each selected project’s question, context, process, material, media, and credits. Validate sources, rights, and ambiguity.

## 3. Design exploration

Use selected real content and a limited analytical reference set. Develop editorial/layout directions, render desktop/mobile views, and have Danny choose/revise based on relationship, readability, media treatment, and authorship. Avoid generic cards, false archive effects, and visual imitation.

## 4. Smallest implementation

Only after content and direction approval, choose the simplest maintainable content/site architecture. Build one complete project path, then a small Index, Work, Writing, and About. Defer framework/CMS/database/graph/media-platform decisions until the tracer shows a genuine need.

## 5. Validate and deploy

Review rendered desktop/mobile experience, keyboard/accessibility, links, media fallbacks, factual content, performance, and deployment configuration. Release only after Danny’s editorial review. Add projects one approved record at a time; add a constellation only when it has real provenance and interpretation.
